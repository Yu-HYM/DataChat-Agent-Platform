# 数仓分层与指标加工说明
来源：离线数仓项目 Q13/14/41/45 加 export_ads_to_mysql.py 流程

## 数仓分层结构
从底向上四层：
1. ODS 贴源层：原始数据 1:1 保留，不做修改。对应 MySQL mall 业务库 user_info product_info order_info
2. DWD 明细层：清洗后的标准化明细记录。空值填充、手机号脱敏、脏数据过滤
3. DWS 汇总层：主题宽表，按天按月预聚合
4. ADS 应用层：面向业务报表、看板、Agent 查询的最终结果。即 mall_ads 数据库的 3 张表

## 指标加工路径
ads_trade_stats：Hive 本地模式一句话 SQL 聚合 DWS 层再导出 MySQL。简单 SUM COUNT，性能好。

ads_repurchase_rate 与 ads_user_rfm 为什么用 Python 而不是纯 Hive SQL：
- 背景：两个指标涉及多 JOIN 与 NTILE 窗口函数，触发 7 加 MapReduce stage
- 问题：Hive 本地模式（小数据自动启用）多 stage 内存不足 OOM 返回 code 2；YARN 模式因 MRAppMaster classpath 缺失无法调度
- 解决方案：Python 直接从业务库 MySQL 读源数据，内存 defaultdict 聚合加手写 ntile5 分档
- 结果落地：结果先写 HDFS 临时文本、临时外部表、INSERT OVERWRITE 转 Hive ORC 内部表、最后 export_ads_to_mysql.py 导出 mall_ads

## 数据日期与快照说明
- 当前 ADS 快照日期：2026-08-19、2026-08-20、2026-08-21 共 3 天
- RFM 窗口：近 30 天数据（相对每个 dt 的回溯 30 天）
- 如需更多天数，需回到离线数仓项目执行 run_pipeline.sh 补日期，再重新 export_ads_to_mysql
- 导出幂等：3 张表都建了主键，用 ON DUPLICATE KEY UPDATE 覆盖写入，重跑不产生重复行
